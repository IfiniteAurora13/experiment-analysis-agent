# 把失败变成可复核的产品证据

这里保存 60 个合成离线回归案例，不是独立冻结验收集。入口是[逐例报告](reports/step2.md)、[完整结果](reports/step2.json)和[交互回放页面](../docs/index.html)。

## 每例需要说明什么

案例包含 ID、任务、标题、来源、类型、严重程度、输入与故障操作、预期状态，以及数值、问题码或版本行为等适用断言。运行结果保留实际状态、接管角色、后续动作和逐维失败原因。

- 数据与口径：缺少分母、水位、跨组用户、重复冲突、孤立订单。
- 时间与方法边界：窗口端点、快照混入、稀疏转化方法不适用。
- 工具与必检：调用失败、坏返回、遗漏护栏、未完成校验。
- 策略与生命周期：允许损失、证据不足、学习意图、事后阈值、旧确认失效、撤回。
- 正常对照与允许降级：合法去重、迟到计入、可选分群失败，避免系统通过“一律拒绝”获得好成绩。

E001–E004 是既有汇总输入与数值参考；E005–E012 是工具故障及其正常对照；C001–C048 是数据包工作流。分维分母不同，不能宣传每种能力都覆盖 60 例。

## 当前交付门槛

1. 全部回归案例通过，关键失败路径零例越权推进；一个案例失败即退出非零，不用平均分掩盖。
2. 数值参考和正常完成必须通过，关键字段或结果缺失不能当作检查通过。
3. 修复后重新确认、版本变化使旧确认失效、撤回清除确认均通过。
4. 已提交回放与当前 Python 语义一致，页面状态测试通过；页面不维护第二套统计引擎。

这些门槛只控制本仓库版本交付，不是生产上线许可。真实模型、真实上游材料与用户任务收益未达到可宣称的验证范围。

## 新失败如何进入这里

先保存最小输入、预期和实际行为，再定位失败层，修复并加入回归；在 bad_cases 中保留同输入前后证据。受控消融、故障注入与生产事故应分别注明，不能混称。规则调整需要更新理由与影响案例，不能只修改预期让分数恢复。

后续由独立设计者增加、冻结验收输入并记录版本。当前参与开发的 60 例继续保留为回归，不能改名冒充 holdout。

```bash
python -m evals.runner --no-write
python -m evals.export_portfolio --check
node --test tests/portfolio_dom.cjs
```

导出刻意改变的行为：`python -m evals.export_portfolio`。`--check` 不改文件；忽略运行时刻、耗时、派生卡片哈希与极小浮点尾差，保留数据版本、状态、证据、动作和数值断言。
