# 从规则评审闭环到可验证的 Agent 闭环

更新日期：2026-10-24。PR #1 已合并。本文件是后续实施与验证计划，不代表所列能力已经实现。

## 当前能做什么，还缺什么

当前已经形成可运行的规则闭环：导入四文件数据包 → 检查口径与完整性 → 确认当前数据版本 → 确定性统计与策略 → 人工复核 / 修复 / 撤回。

数据包主路径不调用模型。旧汇总入口保留可选的 LLM 路由、规划与报告能力；当前计划主要沿预设工具路径执行，尚无针对数据包的多轮澄清、根据工具结果选择补证动作、持久等待与恢复。60 个公开案例只验证离线规则回归，没有证明真实模型收益。

下一轮只处理一个任务：增长 PM 给出实验问题、脱敏实验说明 / 指标字典和导出包，助手定位影响判断的关键缺口，组织补证，最终得到当前版本的人工评审卡或明确接管记录。

## 目标闭环与完成条件

问题与材料 → 提取带来源的口径候选 → 检查冲突 → 提出一个关键澄清 → 等待负责人补证 → 校验确认与版本 → 调用既有分析工具 → 根据返回选择完成、补证、有限重试或人工接管 → 输出有证据的评审卡 → 人工复核与归档。

正确暂停、说明责任与恢复条件也属于有效完成。业务上线仍由负责人在既有流程中决定。新数据到达后沿用已有版本失效规则，不能复用过期确认或复核记录。

## 优先级与可验证交付物

| 优先级 | 要补的能力 | 最小实施范围 | 验收证据 |
| --- | --- | --- | --- |
| P0-1 | Agent 接入数据包主路径 | 输入问题和两类文本材料；提取分母、窗口、币种、支付事件等候选定义并附来源；缺失或冲突时选一个关键问题；完整结构化包继续走规则快路径 | 同一个工作台可完成“材料冲突 → 追问 → 补充 → 确认 → 分析”；保留规则模式对照；不由模型默认填补未知定义 |
| P0-2 | 暂停、恢复与受控执行 | 在现有 ReviewWorkspace 上增加 task_id、待办、材料 / 数据版本、动作记录和持久检查点；等待人工后可恢复；按工具返回选择下一动作 | 重启后能继续原任务；换快照使旧确认失效；同一动作重复提交不会产生重复复核；超预算、不可恢复错误都有终止与接管记录 |
| P0-3 | 模型输出与数值保真 | 数值、策略状态和阻断信息由代码渲染；模型解释须引用工具证据；未知动作、无来源断言、改写数字或材料中的越权指令被拒绝并降级 | 保存成功与失败的真实调用轨迹；注入“忽略 SRM”等材料不能放行；解释不合法时仍能交付固定模板或明确阻断 |
| P1-1 | 一个真实导出适配 | 取得授权的脱敏导出包及一份口径材料；记录字段映射、缺失值、时间单位、重复与水位依据；只支持一个来源 | 字段映射表、负责人核对记录和一张脱敏评审卡；公开仓库只放允许公开的结构与合成替身，不上传业务明细 |
| P1-2 | 真实模型与基线对照 | 固定模型、提示、工具与代码版本；规则和 Agent 共用统计、门禁及风险策略；新增澄清 / 恢复 / 越权 / 超时等端到端任务 | 逐例轨迹、正确完成 / 正确接管、错误类型、耗时、调用成本和接管次数；格式有效率与业务正确率分别报告 |
| P1-3 | 目标用户与交付演示 | 访谈 3 名有实验评审经验的用户，或明确标注代理；执行交叉顺序任务；完成实际工作台视觉与运行验收 | 匿名原始记录、修改次数和最终卡可用性；5 分钟演示正常、阻断、修复恢复；研究失败与反例也保留 |

P0 的代码可以先基于明确标注的合成文本任务完成；P1 的真实材料与用户验证用于检验这些产品假设。不能把外部材料尚未取得改写成已完成验证。

## 实施时的权力边界

候选动作限定为检查材料、提出澄清、请求重导、运行已验证工具、有限重试、生成评审卡、交给人工和完成任务。每一步先通过类型和状态校验。模型不能跳过检查、修改统计数字、改预设风险阈值或执行上线。

所有抽取字段记录候选值、原文位置、缺失 / 冲突状态与确认人。低确定性通过缺口说明和人工确认处理，不用未经校准的自评置信度冒充证据。来源文本作为任务材料处理，不能覆盖系统权限。

重试仅适用于明确的临时工具错误；口径缺失、SRM、跨组和数据未成熟进入等待或接管。调用次数、超时、费用上限可配置且有默认值，超过后保存检查点并给出动作。人工等待不保持模型循环运行。

沿用当前工具与 ReviewWorkspace，不先引入新的 Agent 框架、向量库或多 Agent。模型只接收必要的脱敏口径材料和工具摘要；原始 CSV 在本地计算。

## 真实模型评测如何成立

保留现有 60 例作为规则回归。另准备至少 20 个端到端任务，每例运行 3 次，覆盖完整输入、材料冲突、补证恢复、旧确认、工具异常、无来源断言与输入中的越权指令。

若由独立设计者准备并提前冻结，可记作独立验收集；若开发者参与迭代，则继续标为开发 / 回归集。记录数据版本、模型标识、提示版本、参数、代码提交、输入来源、预期状态、实际动作、关键引用、重试与费用，不把多次运行当作独立用户样本。

下一版交付至少要求：现有规则回归全部通过；已知严重错误零例；所有正常对照任务可完成；预设失败路径可以正确停止、接管或恢复。真实模型可用任务完成率的首轮目标建议设为 90%，这是待验证的工程目标，不是已经取得的成绩；失败必须逐类披露。

严重错误包括：无效数据进入推进建议、输出错误数字、引用不存在的证据、静默放宽风险策略、沿用过期确认。接口超时后正确降级应单独计数，不能隐藏为模型成功，也不能与错误推进混为一谈。

随后用等难、交叉顺序的用户任务比较规则基线与 Agent。材料齐全时允许规则模式表现更好；重点观察材料歧义场景的补证轮次、人工修改和总用时。若没有增量，进一步收窄 Agent 启用条件或保留规则产品。

## 两周最小顺序

| 时间 | 交付 | 验收 |
| --- | --- | --- |
| 第 1–2 天 | 固定三条端到端任务、候选动作与材料结构；同步邀请访谈和申请脱敏导出 | 正常 / 歧义 / 失败恢复各有输入、预期和基线；研究材料取得前不宣称真实验证 |
| 第 3–5 天 | Agent 主入口、证据抽取与关键澄清 | 从文本冲突到人工确认可走通；模型不能自行补齐未知定义 |
| 第 6–7 天 | 持久等待、恢复、预算与错误动作 | 重启恢复、重复提交、换快照、超限与工具失败可复现 |
| 第 8–10 天 | 真实模型端到端评测与数值 / 引用保真 | 20 任务 × 3 次的原始结果与失败分类；不满足门槛则保持试验状态 |
| 第 11–12 天 | 真实导出适配与探索性用户任务 | 有材料和参与者则产出真实记录；否则明确列为阻塞依赖，不用合成记录替代 |
| 第 13–14 天 | 工作台验收、5 分钟演示、README 与简历更新 | 正常、阻断、修复闭环均可演示；简历数字只使用实际完成的结果 |

## 继续停止投入

CUPED、贝叶斯、序贯检验、自动归因、多 Agent、任意 SQL、更多 Provider 和生产自动发布继续暂停。统计能力先做适用性说明与必要的分析师复核，新增方法必须由具体失败与任务需求驱动。

企业单点登录、多人审批流、不可篡改审计和自动回滚不属于这两周的个人原型范围。当前的本地确认与撤回继续按其实际能力表述。
