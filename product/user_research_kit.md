# 下一阶段：用户研究与基线对照任务包

本文件是待执行的研究方案，不是访谈或收益记录。由用户自行邀请有实验评审经验的 PM / 分析师；当前项目没有联系任何外部人员。

## 20 分钟访谈

1. 请回忆最近一次需要给出实验发布判断的经历，展示脱敏后的材料结构。
2. 谁负责定义指标、确认数据齐全和签署最终意见？最常在哪一步返工？
3. 哪些问题你会自己处理，哪些必须找分析师或数据工程师？
4. 已有平台、SQL、表格、模板分别解决什么？本项目哪一步是重复建设？
5. 数据不完整或指标冲突时，你最需要系统给出什么；什么建议会让你不敢使用？

记录材料来源、参与者角色、原始事实、研究者解释和反例。代理用户必须明确标注，不能称为目标用户验证。

## 四个对照任务

A. 数据完备、口径明确：提交一张可用评审卡。
B. 分母缺失或水位未成熟：指出当前最关键问题、接管角色和恢复条件。
C. 主指标提升但护栏越界 / 不确定：分别给出判断，解释预设阈值的作用。
D. 已有评审卡后更换快照或撤回：识别旧确认失效并完成重新确认。

准备两套等难材料，交叉分配规则基线与候选 Agent，避免同一材料重复学习。Agent 必须与基线共用统计、门禁和策略，不允许同时改动评价标准。

## 每次任务记录

记录参与者匿名编号、目标/代理身份、材料版本、方案与顺序、开始结束时间、完成/失败、人工修改次数、错误类型、接管次数、最终卡是否可用、主观困惑与原话。

严重错误包含无效数据仍推进、错误数字或旧确认继续生效。用户明确停下并正确接管，不能简单计成失败。

## 决策方式

先检查严重错误，再比较可用任务完成率、耗时和返工。3 人小样本只做探索，不宣称统计显著。若 Agent 没有减少核对成本，保留规则基线；若收益只发生在某类材料，进一步收窄 Agent 的启用条件。

不得填入未执行的耗时、效率提升或满意度。真实模型评测单独固定模型、提示和重复运行次数；Mock 不计入模型成绩。
