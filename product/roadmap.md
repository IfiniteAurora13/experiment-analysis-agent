## 第一阶段：定位与必检失败门禁

- [x] 收窄目标角色与评审任务，说明非 AI 基线。
- [x] BC005 同输入复现与前后证据，完成性检查进入建议前置条件。

- [x] 固定阻断报告、工具故障、坏返回、预算耗尽及可选分群降级回归。

## 第二阶段：数据契约与失败恢复

- [x] 固定 assignments.csv、orders.csv、contract.json、manifest.json。
- [x] 用户级随机、全部入组分母、连续 168 小时、CNY、去重与零值规则。
- [x] 上游完整性水位与声明，窗口未成熟不计零。
- [x] 同组冲突、跨组、孤立订单、重复冲突、迟到、窗口边界、快照混入检查。
- [x] 原始订单按用户聚合后计算均值、样本方差与转化人数。
- [x] 口径确认绑定数据包版本；更新后旧卡失效；本地人工复核与撤回。
- [x] 本地工作台上传、CLI 持久记录及可下载中文评审卡。
- [x] 稀疏转化方法适用性边界，BC006 受控消融证据。
- [ ] 对接一个获得授权的真实导出包，记录字段与上游差异。

## 第三阶段：策略与作品集证据

- [x] 一个主指标与一个护栏的预设允许损失规则。
- [x] 允许损失内、越界、证据不足、学习意图区分；事后阈值阻断。
- [x] 60 个合成回归案例，逐类分母、预期/实际和来源标注。
- [x] 11 条真实 Python 离线回放，包含正常、阻断、修复和旧确认失效。
- [x] 浏览器页移除独立统计计算；导出语义与页面状态纳入 CI。
- [x] README、数据契约、失败记录和求职叙事按实际实现更新。
- [ ] 由独立设计者新增并冻结验收集；不把既有 60 个回归例重命名为 holdout。
- [ ] 固定模型与提示版本，单独验证真实模型理解、澄清、工具行为和文案保真度。
- [ ] 访谈 3 名目标用户，或明确标注的代理用户，验证任务与已有工具。
- [ ] 交叉任务对照基线与 Agent，记录耗时、修改、错误和接管；不虚构收益。

## 下一阶段的验收

先取得研究或真实材料的增量证据，再决定 Agent 是否值得加入主流程。测试通过不代替场景验证，用户研究计划不代替访谈记录，Mock 不代替模型成绩。

访谈、对照任务和记录格式见 user_research_kit.md。不能宣称已经完成原先设想的 40 开发 + 20 冻结验收；当前 60 例全部为回归。

## 继续暂停投入
