# 分阶段优化路线

所有未勾选项目都是计划，不得写成简历成果。

## 第一步：定位与必检失败门禁

- [x] 固定目标角色与评审任务，说明非 AI 基线和证据空白。
- [x] 复现质量检查失败仍产生正向发布建议的路径，保存同输入前后证据。
- [x] 增加 PASS / FAIL / UNKNOWN 必检状态与 BLOCKED / READY 评审状态。
- [x] 在建议生成前检查质量、全部指标结果和统计校验；覆盖建议工具失败与预算耗尽。
- [x] 被阻断报告使用固定模板，显示接管角色和重跑条件，效果解读暂停。
- [x] 可选分群失败保留已验证总体结果，覆盖正常路径以防一律拒绝。
- [x] Eval 增至 12 例，增加最终模板文案安全检查与失败退出码。
- [x] 浏览器页降级为统计示意，不冒充完整工作流执行记录。

## 第二步：固定数据契约与脏数据闭环

- [ ] 访谈 3 名目标用户或明确标注的代理用户，验证任务与现有基线。
- [ ] 固定 assignments.csv + orders.csv + 实验/指标契约，先做一个导入适配器。
- [ ] 固定分流单位、分母、7 天观察窗、时区、去重与零值规则。
- [ ] 将入组用户数与指标观测数分开；数据成熟度需要上游证据，不能用最大时间戳代替。
- [ ] 提供干净包，以及重复、缺失、跨组、迟到、窗口未成熟等脏数据变体。
- [ ] 增加口径确认、修复重跑、数据/口径更新后旧卡失效；仅本地流程，不宣称企业权限系统。
- [ ] 交付导入规范、确认记录、可复现变体和一张完整评审卡。

## 第三步：风险分级、评测页面与求职叙事

- [ ] 一个主指标与一个护栏，事先确认允许损失界值和接管等级。
- [ ] 区分超出允许损失、尚不能排除损失、满足约定边界；数据质量问题不允许业务豁免。
- [ ] 40 个开发案例 + 20 个冻结案例，按故障来源与模板分组，避免泄漏。
- [ ] 单独记录真实 LLM 理解/追问/最终文案保真度；Mock 不计为真实模型表现。
- [ ] 核心严重错误为 0、决策及接管正确率目标 >=95%，逐类显示分母和剩余失败。
- [ ] 发布正常完成、正确阻断、恢复成功三条回放及逐例评测页面。
- [ ] 完成小型基线对照并记录耗时、修改次数与错误；不虚构收益。
- [ ] 按真实结果更新 README、四句简历和一次失败设计调整的面试叙事。

## 两周安排

第 1–2 天：定位、访谈和基线；第 3–4 天：数据契约；第 5–7 天：失败恢复与版本确认；第 8–11 天：分层案例、模型和用户对照；第 12 天修复；第 13–14 天整理证据与材料。当前先完成第一步，后续依赖真实验证继续调整。

## 暂停投入

不扩展 CUPED、贝叶斯、序贯检验、多 Agent、任意 SQL、更多 Provider、自动上线或第二套统计引擎。保留现有统计内核、来源标记、Trace 与有价值的回归测试。驱动分析降级为公式说明，不宣传自动归因。
