# 产品策略简报

## 用户与一次任务

目标角色是电商增长 PM，已有实验平台或导出渠道，但还需协调口径和数据完整性，才能准备发布评审材料。任务限定为商品详情页两组、用户级随机、固定周期实验，输出一张人工评审卡。

这个角色与痛点是待验证假设。当前没有目标用户研究、生产接入或商业收益证据。

## 已运行的产品闭环

四文件导出包 → 校验口径和水位 → 记录当前版本确认 → 用户级统计 → 必检门禁 → 预设风险策略 → 负责人复核 / 修复 / 撤回。

主指标为入组后连续 168 小时支付用户转化率，分母是全部唯一入组用户。护栏为同窗口 CNY 支付 GMV / 用户，未扣退款。全部统计和业务规则由确定性代码执行。

## 为什么先做非 AI 基线

已标准化输入的统计、规则和报告不依赖模型。先用同一套数据、统计和策略建立基线，避免把“用了 LLM”当成收益。

Agent 的候选增量是跨材料定位口径冲突、提出最重要的澄清问题、组织补证路径。目前尚无收益对照，产品主路径不强制使用模型；旧实验室的 LLM 规划保留为可选能力。

## 关键取舍

- 一个导出适配器、一个主指标、一个护栏，优先把分母、窗口、去重和迟到处理做清楚。
- 无订单只在完整性声明覆盖后计零；源系统声明仍需人工核对，不把内部一致性校验当作全链路认证。
- 必检未完成不能推进；可选分群失败可保留已验证的总体结果。
- 预设允许损失和学习意图区分不同判断；数据有效性不允许被风险偏好豁免。
- 不支持稀疏事件时明确转交分析负责人，不为了能力矩阵增加高级统计方法。
- 字节级数据包版本绑定确认；本地署名和撤回演示责任与失效机制，不宣传企业审批权限。

## 评测与验证状态

现有 60 个合成回归场景，覆盖既有流程、工具故障、原始数据、口径、策略、时间边界和版本。另有工作台端到端与页面状态测试，回放由真实 Python 执行导出，并在 CI 校验语义一致。

这些均非独立冻结集或真实模型评测。下一步按 user_research_kit.md 验证目标用户与基线收益；如 Agent 没有减少返工，就维持规则产品而不扩展动态规划。
